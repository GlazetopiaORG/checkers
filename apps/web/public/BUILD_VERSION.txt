Phase 5.0.14 — Session token lifetime + resume-vs-new on /checkers
  - CHECKERS_SESSION_TTL_MINUTES default raised: 15 → 1440 (24 hours)
  - JWT exp and the DB row's expires_at both use the same TTL
  - NEW: POST /api/checkers/session/start-or-resume
    - HMAC-protected, bot-only (same auth scheme as /session/start)
    - Returns { kind: 'new' | 'resumed', sessionId, token, expiresAt,
                gameUrl, resumed }
    - Resume path:
        * Re-mints JWT for the existing sessionId (old browser link
          is invalidated — token_hash is replaced)
        * Bumps the row's expires_at by another 24h
        * Returns the same sessionId so no duplicate marks possible
  - /checkers bot command:
    - Now calls start-or-resume instead of start
    - If kind === 'resumed': renders new resumed-session embed +
      Resume Game link button + Forfeit & Start New danger button
    - Forfeit & Start New: cancels unfinished session via
      /session/cancel, then creates a fresh one and replaces the embed
  - Expired-token UX:
    - GameClient maps UNAUTHORIZED + "expired" message → 'expired' phase
    - Dedicated expired-phase render:
      "This game link expired. Return to Discord and run /checkers
       to get a fresh resume link."
